# Jarvis iPhone 第一版设计规格

## 1. 目标

构建一款可独立使用并能控制 Windows 电脑的原生 iPhone Jarvis。第一版以同一 Wi‑Fi 下的可靠连接为边界，提供语音与文字对话、手机本地任务、电脑白名单操作，以及所有跨应用操作的确认机制。

第一版不包含公网远程控制或后台永久静默监听。付款、删除文件和输入密码永久不纳入允许工具。

## 2. 已确认的产品决策

- 原生技术：SwiftUI。
- 构建服务：Codemagic 云端 Mac。
- 分发：加入 Apple Developer Program 后通过 TestFlight。
- 模型：混合模式。电脑在线时优先使用电脑本地模型；电脑不可用时，经用户许可切换云端。
- 连接范围：第一版仅限同一 Wi‑Fi，稳定后再单独设计公网远程。
- 语音入口：点击或按住语音胶囊、Siri 快捷指令、iPhone 操作按钮、锁屏和主屏幕小组件。
- UI：A「对话优先」布局，2「极夜黑」视觉风格。
- 跨应用操作：纳入第一版，但每次执行前必须确认。

## 3. 系统架构

系统分成三个边界清晰的部分。

### 3.1 JarvisIOS

原生 SwiftUI iPhone 应用，负责：

- 语音录制、语音转文字和文字输入。
- 对话界面、本机对话历史、提醒和笔记。
- 电脑连接状态、本地模型状态和任务状态展示。
- 动作预览、确认、取消和结果展示。
- App Intents、App Shortcuts、操作按钮入口和 WidgetKit 小组件。
- 配对密钥的 Keychain 存储。

### 3.2 JarvisBridge

现有 Windows Jarvis 的局域网配套服务，负责：

- 显示一次性配对二维码。
- 验证已配对 iPhone 的身份和请求签名。
- 将协议命令映射到现有白名单工具。
- 返回任务生命周期事件和明确错误。
- 拒绝未知工具、过期请求、重复请求和未确认的敏感操作。

Bridge 仅绑定局域网接口，不配置公网端口映射。

### 3.3 SharedProtocol

iPhone 与电脑共同遵守的版本化协议。协议定义：

- 配对请求、配对确认和设备撤销。
- 对话请求与响应。
- 工具提案、风险等级、动作预览和确认。
- 任务状态：准备、等待确认、执行中、完成、失败、取消、结果未知。
- 错误码、请求标识、时间戳和幂等键。

协议以向后兼容为目标；不认识的版本或字段不得降级为任意执行。

## 4. iPhone 界面

### 4.1 首页

采用 A「对话优先」结构：

- 顶部：Jarvis 标题和电脑连接状态。
- 中部：语音核心、问候语和当前语音状态。
- 对话区：用户与 Jarvis 的自然语言消息。
- 设备卡片：Windows 主机、本地模型和网络状态。
- 底部：文字输入框与语音胶囊。
- 主导航：对话、任务、设备。

### 4.2 视觉风格

采用「极夜黑」：OLED 友好的黑色透明表面、白色主文字、低饱和辅助文字和克制的状态色。界面不使用装饰性仪表盘或无功能卡片。

### 4.3 关键状态

首页必须清晰区分：空闲、正在聆听、正在识别、正在思考、等待确认、执行中、完成、失败和电脑离线。状态不能只通过颜色表达。

## 5. 第一版功能

### 5.1 iPhone 独立功能

- 语音和文字对话。
- 本机对话历史。
- 创建提醒和笔记。
- Siri 快捷启动。
- 操作按钮、锁屏小组件和主屏幕小组件入口。
- 电脑离线时，经许可切换云端对话。

### 5.2 电脑联动功能

- 扫描二维码完成一次性配对。
- 打开或激活白名单程序。
- 控制系统音量。
- 搜索和打开允许目录中的文件。
- 操作微信：搜索联系人、预览消息、确认后发送。
- 查询任务结果和失败原因。

### 5.3 第一版禁止与延期

禁止：

- 付款。
- 删除文件。
- 输入、读取或代填密码。

延期：

- 公网远程控制。
- 后台永久静默监听“你好，Jarvis”。

## 6. 数据流

1. 用户通过语音胶囊、Siri、操作按钮、小组件或文字输入发起请求。
2. iPhone 在本机录音并产生可见的识别文本。
3. 电脑在线时，请求经局域网加密连接交给 JarvisBridge 和电脑本地模型。
4. 电脑离线时，iPhone 说明原因；只有用户允许后才使用云端模型。
5. 普通回答直接返回 iPhone。工具动作先转换为白名单提案。
6. 跨应用和对外动作在 iPhone 显示目标、内容和风险；用户确认后才执行。
7. JarvisBridge 返回任务状态，iPhone 按顺序展示最终结果。

## 7. 安全和隐私

- 电脑二维码包含一次性配对材料，不包含可长期复用的明文密钥。
- 长期设备密钥分别存放在 iPhone Keychain 和 Windows 凭据存储。
- 所有控制请求包含设备身份、请求标识、时间戳、幂等键和完整性校验。
- 未配对设备、过期请求、篡改请求和重复敏感请求全部拒绝。
- 跨应用操作必须确认；发送消息必须展示联系人和完整消息预览。
- 语音识别不确定时只展示文本，不生成可执行确认。
- 对话历史默认只存 iPhone 本机。
- 敏感内容不写入操作日志，也不存入 Codemagic 配置或源码。
- 云端回退默认关闭自动切换，每次由用户许可。

## 8. 异常处理

- 电脑离线：保留请求草稿，提供重试或经许可进行云端对话。
- Wi‑Fi 改变：断开电脑控制连接，并要求重新确认目标电脑。
- 找不到程序、文件或微信联系人：停止操作并返回具体原因。
- 请求超时：显示“结果待确认”，不自动重复执行敏感动作。
- 协议版本不兼容：拒绝控制命令，并提示升级对应端。
- 权限缺失：说明所需 iOS 权限及其用途，不循环弹窗。
- 云端构建失败：保存构建日志和测试结果，不生成可分发版本。

## 9. 测试策略

### 9.1 JarvisIOS

- 语音文本解析、连接状态、权限和本机数据单元测试。
- 动作预览、确认、取消及禁止工具测试。
- 首页、录音、离线、确认和错误状态界面测试。
- App Intents 与小组件入口测试。

### 9.2 JarvisBridge

- 配对、认证、设备撤销和请求签名测试。
- 白名单映射、风险策略和错误码测试。
- 幂等、重复发送防护、断线和超时测试。

### 9.3 联调

第一版关键路径为：

`连接电脑 → 发出语音请求 → 生成工具提案 → 显示预览 → 用户确认 → 电脑执行 → iPhone 显示结果`

微信联调必须验证联系人错误、识别文本错误、取消、断线和结果未知时均不会重复发送。

## 10. 构建和分发

- 源码在 Windows 开发环境中维护并通过 Git 提交。
- Codemagic 使用 `codemagic.yaml` 运行原生 iOS 编译和模拟器测试。
- 未加入 Apple Developer Program 前，仅运行无需签名的构建和测试。
- 加入计划后，通过 App Store Connect API 集成自动签名并上传 TestFlight。
- 签名证书、API 私钥和发行凭据只放在 Codemagic 加密凭据存储中。

## 11. 第一版成功标准

- iPhone 能通过已确认的四种入口启动 Jarvis。
- 同一 Wi‑Fi 下能可靠连接已配对电脑并使用本地模型。
- 低风险电脑工具能返回明确结果。
- 跨应用和对外操作未经确认绝不执行。
- 敏感请求断线或超时时不自动重试。
- Codemagic 能完成无签名编译、自动化测试；加入开发者计划后能产出 TestFlight 构建。
