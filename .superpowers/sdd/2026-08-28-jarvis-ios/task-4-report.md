## Protocol and security decisions

- `BridgeRequest`, `BridgeResponse`, `RequestKind`, `TaskState`, and `Risk` use
  the exact Python snake-case field names and wire values. Unknown enum values
  throw `BridgeProtocolError.unknownEnumValue`; they never become a success or
  other default state.
- Request payloads use a typed recursive `JSONValue`. `canonicalData()` uses a
  purpose-built ASCII JSON serializer rather than Foundation's presentation
  choices: object keys are sorted in Python code-point order via UTF-8 lexical
  order, separators are compact, `/` remains unescaped, controls use Python's
  short/lowercase escapes, BMP Unicode uses lowercase `\uXXXX`, and non-BMP
  Unicode is emitted as lowercase UTF-16 surrogate pairs.
- `RequestSigner` requires an exact 32-byte secret and generates CryptoKit
  HMAC-SHA256 as exactly 64 lowercase hexadecimal characters. The checked
  fixture was generated by the Task 1 Python implementation.
- `KeychainDeviceStore` keeps device ID, device secret, and certificate
  fingerprint as three generic-password items. Both add and update paths apply
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`. The Security calls are
  behind an injectable wrapper used by deterministic tests.
- `DeviceCredentials`, `KeychainItem`, `BridgeRequest`, `PairingPayload`, and
  `BridgeClient` provide redacted descriptions so a debug print does not expose
  payload content, device secret, certificate fingerprint, or pairing proof.
- The secure production client initializer creates its transport through a
  `PinnedTransportFactory` using the stored fingerprint. The test initializer
  accepts an injected `BridgeTransport`. `PinnedCertificateDelegate` accepts
  only a server-trust challenge whose leaf DER SHA-256 matches the scanned
  lowercase fingerprint; mismatch, missing/malformed trust, and every other
  authentication method are cancelled.
- Bridge URLs must use HTTPS, contain no credentials/query/fragment/base path,
  and resolve syntactically to an approved private/loopback/link-local address
  or local hostname. Public IPv4/IPv6, wildcard-style public values, and legacy
  integer/hex numeric host forms are rejected; there is no HTTP fallback.
- `submit`, pairing claim, confirmation, and cancellation send once. Ambiguous
  timeout, connection-loss, or cancellation errors become `.resultUnknown` and
  are never automatically resubmitted. Only authenticated `GET` task status is
  eligible for the bounded safe-read retry policy.
- Status, confirm, and cancel requests bind the signed device owner and
  `target_request_id` to the URL path. Cancellation intentionally uses the
  Python server's `POST /v1/tasks/{request_id}/confirm` route with request kind
  `cancel`.
- Pairing claim creates a transport from the QR fingerprint before sending the
  unsigned one-time claim. Returned URL-safe Base64 credentials are validated
  as version 1, nonempty device ID, and exactly 32 secret bytes before anything
  is written to Keychain.
